## 2. Targeted Quality Fixes Implemented

### Fix 1: Data Health Score — 4-Pillar Penalty Implementation & Caps
- **Type Contamination Penalty ($P_{\text{types}}$):** Implemented in `scripts/analyze_csv.py`. Detects non-empty string cells in numeric columns that cannot be parsed into numbers (e.g. `"ERROR"`, `"corrupt"`, `"invalid"`).
- **Exact Penalty Formulations & Caps:**
  - $P_{\text{missing}} = \min(40.0, \text{Avg Missing \%} \times 1.5)$
  - $P_{\text{duplicates}} = \min(30.0, \text{Duplicate Row \%} \times 2.0)$
  - $P_{\text{outliers}} = \min(20.0, \text{Numeric Outlier \%} \times 1.0)$
  - $P_{\text{types}} = \min(10.0, \text{Numeric Type Contamination \%} \times 1.0)$
  - $\text{Health Score} = \max(0.0, \min(100.0, 100.0 - \sum P))$.
- **Status Tiers:**
  - $\ge 85.0$: `"High Reliability"`
  - $70.0 \le \text{Score} < 85.0$: `"Acceptable (Caveats Disclosed)"`
  - $< 70.0$: `"Needs Review (High Risk of Skewed Findings)"`
- **Outlier Philosophy:** Statistical outliers are explicitly flagged as high-leverage observations for review; **never automatically treated as bad data or discarded**.

### Fix 2: Duplicate Handling & Dual Reporting
- Evaluates duplicate count, duplicate percentage, and **duplicate revenue exposure** ($\sum \text{Revenue}$ of duplicate entries).
- Financial KPIs are emitted with dual reporting views:
  - `all_rows`: KPIs across all records (inclusive).
  - `deduplicated`: KPIs with exact duplicate rows isolated.
  - `duplicate_exposure`: Isolated count, revenue, cost, and profit impact.
- Duplicates are never silently removed.

### Fix 3: Average Order Value (AOV) by Unique Orders
- Detects order ID columns via `ORDER_ID_HINTS` (`Order_ID`, `invoice_no`, `transaction_id`, etc.).
- When Order ID is present: Aggregates line-item revenue by unique order ID before dividing by order count ($\text{Total Revenue} / \text{Unique Orders}$). Emits `aov_type: "unique_orders"`.
- When Order ID is absent: Falls back to line-item average and labels it `aov_type: "line_item_average"`.

### Fix 4: Zero-IQR Outlier Edge Case
- When $\text{IQR} == 0$ (central 50% of data values are identical):
  - Constant column ($s == 0$): Sets bounds to min/max and reports 0 outliers.
  - Repeated values with extreme observations ($s > 0$): Employs a robust $2.5 \times s$ fence from the mean ($\mu \pm 2.5s$) to flag the extreme observation without misclassifying repeated modal values.
- Datasets with $N < 4$ safely bypass outlier fences (0 outliers).

### Fix 5: Financial Integrity & Consistently Paired Rows
- **Paired-Row Rule:** Gross profit and weighted margin are derived strictly over valid rows where both revenue and cost (or direct profit) are present.
- **Unpaired Disclosure:** Any rows with revenue lacking cost data are tracked under `unpaired_revenue_rows` and explicitly disclosed in `analytical_notices`.
- **Zero/Negative Revenue Guardrail:** If paired revenue $\le 0$, `weighted_margin_pct` evaluates to `None` to prevent misleading inverted percentages.

### Fix 6: Scope Clarification in SKILL.md
- Explicitly documented the boundary between:
  - **Deterministic Helper (`scripts/analyze_csv.py`)**: Data ingestion, 4-pillar health scoring, dual KPI views, AOV aggregation, segment breakdowns, monthly time-series groupings, zero-IQR safe outlier detection.
  - **Agent Reasoning Layer**: Driver decomposition (price vs volume vs cost), what-if sensitivity simulations (stating elasticity assumptions), forecasting (trend analysis over time-series data), executive report synthesis, and Decision Log entries.
- The Python script is not falsely claimed to implement what-if simulations or forecasting; it provides the underlying historical aggregations.
